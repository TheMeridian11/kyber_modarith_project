## Conditions and thesis interpretation

The retained conditions are an Intel Core i9-12900KS reported by Ubuntu 24.04.2 under WSL2, x86_64, GCC 13.3.0 and the same normal -O3 flags for both variants. The runner pinned the guest process to logical CPU 0. Each of five pairs per parameter used 100 warm-up and 1000 measured exchanges, seed 1 and CLOCK_MONOTONIC_RAW nanoseconds. Three separate KEM operations were timed per exchange; fixture generation, secret checks and output formatting were outside the intervals. Deterministic APIs exclude operating-system randomness. Host OS details, power mode, background load and physical-core placement were not recorded and remain unknown. Guest affinity is not a physical-core placement guarantee.

The reduction counts and assembly from [RUN-0001](EXP-002-RUN-0001.md) explain the changed work: 384 Montgomery calls per dot product instead of EXP-001's 384K, with Barrett counts unchanged. The implementation also changes loop structure, memory traffic, local stack use, function size and local stack-canary coverage. These effects occur together; this run does not isolate how much time each contributes. The stronger Kyber768 result is observed, while a specific microarchitectural explanation remains untested.

The prior range, invalid-input compatibility and assembly assessments remain conditions of retention. The new timings do not establish constant-time behaviour, statistical leakage resistance, memory safety, power/EM resistance or fault resistance. The absent local canary in the EXP-002 dot-product function remains a documented hardening tradeoff under unchanged compiler flags. I have not measured performance on adversarial input classes or other compilers/targets.

These are incremental gains over EXP-001. I do not add or multiply the median percentages from separately collected comparisons to claim a total gain over the original reference. The later [final direct comparison](../final_comparison.md) supplies the cumulative original-reference result. No additional repeat is needed merely to proceed from this consistent initial result; broader generalisation would require planned replication under recorded conditions.

## Retention decision

I close EXP-002's initial validation/timing evaluation with outcome supported within this run and decision retain as the reference for the subsequent inverse-transform trial. All raw/derived artifacts and the prior evidence remain unchanged.

[EXP-003](../experiments/EXP-003-staged-invntt.md) now tests a fixed inverse-NTT Barrett schedule on top of EXP-002. Its first run establishes correctness, bounds, counts and assembly; it will not measure speed. If accepted, a later fresh EXP-002/EXP-003 timing comparison will measure its conditional incremental effect. It is not an independently isolated treatment on the original reference.
