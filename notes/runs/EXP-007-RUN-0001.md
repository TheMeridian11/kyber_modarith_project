This ties the observed sensitivity to actual generated code rather than an optimised-away test.

No new marked-secret branch/address finding emerged in original, EXP-005 or EXP-006 on these paths. The result complements the existing range/scale/narrowing arguments, deterministic compatibility, invalid-input checks and exercised UBSan evidence. Those earlier correctness checks were not rerun by Memcheck. EXP-002's inherited general-dot local-canary removal remains a documented hardening tradeoff; quiet flow reports neither erase that observation nor establish memory safety. Keygen protection observations remain scoped to their recorded assembly.

Memcheck does not detect operand-dependent instruction latency, every cache/microarchitectural mechanism, unexecuted branches, power/EM or faults. The integration probe is IND-CPA decryption, not complete KEM reencryption and implicit rejection. A valid dynamic result is therefore one layer of the required implementation-security assessment. I keep EXP-005 as the primary provisional closing candidate and EXP-003 as an explicit comparator/fallback.
